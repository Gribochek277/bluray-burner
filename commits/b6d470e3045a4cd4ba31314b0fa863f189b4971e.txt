message:
Silence BrokenPipeError noise; compute labels with one python call
plan_first_disc stops reading unit names as soon as the next unit does not
fit, closing the pipe under list_units' python, which then printed an ugly
'BrokenPipeError while flushing sys.stdout' (non-fatal, but alarming).
Python emitters now die silently on SIGPIPE like standard Unix tools.

compute_label no longer runs one find per unit over the network; it takes
the unit keys and derives the label from basenames in a single python call
(same rule as the dry-run planner), keeping the disc display snappy on
gvfs sources.
